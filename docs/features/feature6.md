# Feature 6 — призначення рецензента (гнучкий момент)

## Мета

Секретар призначає рецензента **після затвердження теми**. Момент призначення **не блокує** виконання роботи студентом: можна призначити одразу після теми або пізніше — уже під час перевірок допуску (до кроку «Рецензія»).

Статус життєвого циклу після затвердження теми: **`WorkInProgressByStudent`** («Робота в процесі»), numeric value `4`.

> Раніше (commit `RequireReviewerBeforeWork`) рецензент був обов’язковим **до** завантаження роботи; цю вимогу скасовано.

## Цільовий workflow

```text
AwaitingSupervisor
  → SupervisorConfirmed
  → TopicInReview
  → WorkInProgressByStudent    // тема затверджена; студент може працювати
  → DocumentsInProgress        // після DeclareWorkReady
  → ReadyForAdmission
  → Admitted
```

Прогрес-бар у UI — **8 кроків** (окремого кроку «Рецензента призначено» немає):

1. Вибір керівника  
2. Тема на розгляді  
3. Робота виконується  
4. Відгук керівника  
5. Нормоконтроль  
6. Антиплагіат  
7. Рецензія  
8. Допуск до захисту  

| Before | Action | After |
|--------|--------|-------|
| `TopicInReview` | Завідувач затверджує тему | `WorkInProgressByStudent` |
| `WorkInProgressByStudent` | Студент завантажує роботу / `DeclareWorkReady` | без змін / `DocumentsInProgress` |
| Тема затверджена, рецензента ще немає | Секретар призначає рецензента | `ReviewAssignmentStatus=Assigned` (lifecycle лишається за поточним етапом) |
| Перші три перевірки пройдені, рецензента немає | Секретар призначає рецензента | `CurrentAdmissionStep=ExternalReview` |

## Бізнес-правила

| # | Правило |
|---|---------|
| R1 | Призначати рецензента може **лише секретар** сесії (`DiplomaAction.AssignReviewer`) |
| R2 | Рецензент — **активний працівник кафедри** сесії диплома |
| R3 | Призначення дозволене **після затвердження теми**, доки диплом **не admitted** і рецензія **не Completed** |
| R4 | Призначення можливе **і після** старту admission checks / виконання роботи |
| R5 | Якщо вже пройдено відгук, нормоконтроль і антиплагіат — після Assign крок стає `ExternalReview` |
| R6 | Upload роботи дозволений з `WorkInProgressByStudent` (+ `TopicApproved`, `DocumentsInProgress`, `ReadyForAdmission`); рецензент **не** потрібен |
| R7 | `DeclareWorkReady` — зі статусу `WorkInProgressByStudent` і за наявності файлу роботи; рецензент **не** потрібен |
| R8 | У UI повторне призначення (заміна) заблоковане, поки статус не `NotAssigned`; у домені заміна дозволена до `Completed` |
| R9 | До допуску рецензія має бути завершена (`ReviewAssignmentStatus=Completed`) |

## Не в scope

- Зняття рецензента після `Completed`
- Окремий lifecycle-статус «Рецензента призначено»
- EF global query filters

## Persistence

`LifecycleStatus = 4` знову означає **`WorkInProgressByStudent`**. Окремої data-міграції для відкату не потрібно: значення в БД не змінювалось.

## UI / локалізація

- Badge: «Робота в процесі»
- Dashboard секретаря: bucket `WorkInProgressByStudent`
- Секретар може призначити рецензента на картці диплома, поки тема затверджена і рецензент ще не призначений
- Студенту не показується блокування «очікуйте рецензента» для upload / DeclareWorkReady
